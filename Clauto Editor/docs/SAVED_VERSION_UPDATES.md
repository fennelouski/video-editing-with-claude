# Saving a local update as a version

Working milestone M27 adds an optional **Save as new version** action to a verified local export. A user can keep giving feedback while the save runs. Saving is a durable checkpoint, not a required end to a conversation.

The save keeps the selected export's portrait/landscape framing, interval, audio processing, sound effect and composed graphic layers. It copies every hash-listed output into a new `cuts/vNNN/exports` folder and rewrites references to generated files into that permanent folder. References to original footage and earlier saved layers stay linked to their preserved sources. The verified build export and all earlier versions remain available.

The new record inherits the exact parent plan, brief and script. It preserves the intersection of the parent’s frozen duration limits and current project limits, checks the actual saved XML duration and keeps an exact project-settings snapshot. A short separate export cannot silently remove a main-version minimum; explicit duration-revision workflows remain separate. A hash-bound lineage receipt names the parent, export recipe, copied outputs and saved timeline/movie. It explicitly records no new editorial, scientific or production approval. The handoff PDF includes the inherited script as reference and layers from the saved XML; it says the edited audio has not been transcribed again. It never reuses an old transcript as if it described newly edited audio.

Publication reserves a distinct version folder under the common project lock, performs the large copy outside that lock, then reacquires the lock. Before updating the current-version pointer it checks the physical project, expected current version plus the current-pointer file revision (including an explicit restore to the same version), source/export identity and copied inputs/outputs. A concurrent version selection or changed source causes refusal. Interrupted folders remain as incomplete retained work, are excluded from accepted history, and are never overwritten by the next save. A retry of an already published derivative returns the existing version without changing a newer current selection.

The application owns and joins a save through project changes and quit. Its result belongs to the captured export/project; it does not overwrite another project's notices or retarget a playing review session. A failed save retains the requested name and result in the project session, blocks a silent quit and can be retried or explicitly acknowledged with Keep verified export only. Users open the resulting version in Versions.
